# Как запустить и дать протестировать другим в одной Wi‑Fi сети

Есть два режима. Выберите по ситуации.

- **Локальный режим (по умолчанию).** Бэкенд не нужен. Каждый, кто открыл сайт,
  работает со своей копией данных в браузере (IndexedDB). Годится, чтобы просто
  «пощупать» интерфейс.
- **Серверный режим (Фаза 4).** Запускается сервер, данные хранятся на нём.
  Каждый вводит своё имя на входе — у каждого своё пространство, доступное с любого
  устройства. Это то, что нужно для совместного тестирования.

Ваш IP в текущей сети: **`192.168.31.208`** (проверить: `ipconfig` → строка «IPv4»).
Дальше подставляйте свой актуальный адрес.

---

## Вариант A — быстро показать интерфейс (без сервера)

```powershell
npm install
npm run dev -- --host
```

Vite напечатает строку **Network:** `http://192.168.31.208:5173/`.
Коллеги в той же Wi‑Fi открывают этот адрес на телефоне/ноутбуке. У каждого — свои
локальные данные (ничего общего, ничего на сервере).

---

## Вариант B — совместное тестирование через сервер (Фаза 4)

Нужно **два процесса**: бэкенд (порт 8000) и фронтенд (порт 5173).

### 1. Запустить бэкенд

```powershell
cd server
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Проверка со своего компьютера: `http://localhost:8000/api/health` → `{"status":"ok"}`.
(БД по умолчанию — файл `server/fin_reports.db`, SQLite, ставить ничего не надо.)

### 2. Указать фронтенду адрес сервера

В корне проекта создайте файл **`.env`** (рядом с `.env.example`):

```
VITE_API_URL=http://192.168.31.208:8000
```

Важно: именно IP компьютера‑сервера, **не** `localhost` — иначе телефоны коллег
будут стучаться сами в себя.

### 3. Запустить фронтенд

```powershell
npm install
npm run dev -- --host
```

Откройте `http://192.168.31.208:5173/`, войдите под своим именем, поработайте.
Данные уходят на сервер под вашим именем.

### 4. Коллеги подключаются

Они на своих устройствах в той же Wi‑Fi открывают **`http://192.168.31.208:5173/`**
и входят под своими именами. У каждого — своё пространство. Кто уже заходил — увидит
`GET /api/workspaces` (или страницу `/docs` сервера).

## Если не открывается с других устройств — брандмауэр Windows

При первом запуске Windows обычно спрашивает «Разрешить доступ» — нажмите
**«Разрешить в частных сетях»**. Если пропустили, разово откройте порты (PowerShell
от администратора):

```powershell
New-NetFirewallRule -DisplayName "Fin API 8000"  -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000
New-NetFirewallRule -DisplayName "Fin Web 5173"   -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5173
```

Ещё проверьте, что сеть отмечена как **«Частная»**, а не «Общедоступная»
(Параметры → Сеть и Интернет → свойства сети).

## Частые вопросы

- **Данные пропали после перезагрузки браузера в серверном режиме?** Не пропадут —
  они на сервере, войдите тем же именем. В локальном режиме данные привязаны к
  конкретному браузеру.
- **Сбросить всё на сервере?** Остановите сервер и удалите `server/fin_reports.db`
  (для SQLite) — при следующем старте создастся заново.
- **Продакшн вместо dev-сервера фронта?** `npm run build`, затем
  `npm run preview -- --host --port 5173` — раздаёт собранную статику.
- **MySQL вместо SQLite?** См. `server/README.md`, раздел «Переключение на MySQL 8».
